# Eligibility override archives

Source: https://github.com/mattisklein/project-linwood
Pinned commit: b9438cec65b384974a9c6be6169ec9fa1e64c83a
Author: mattisklein. MIT license reproduced in LICENSE.

`enable.data` is the original 631-byte `override_enable_gm.data`.
`reset.data` is the original 320-byte `override_reset.data`.
Both were generated using Apple's NSKeyedArchiver; never reserialize these as
ordinary preference plists. The runtime verifies their SHA-256 hashes.

Enable overrides SIRI_MODE (155), AMERICIUM (96), GREYMATTER (122) to answer 4;
AMERICIUM includes OS_ELIGIBILITY_CONTEXT_LINWOOD_AVAILABILITY = 2.
Reset is a valid archive with an empty overrideMap, not an empty file.

## iPhone Mirroring (added 2026-11-14)

`OS_ELIGIBILITY_DOMAIN_IRON` is enum **27**, "iPhone Mirroring", device classes
iPhone and Mac. It is a plain answer with no context key, and it lives in the
same `os_eligibility` vault as AMERICIUM, so it is one more key in the *same*
override archive. The EU block is evaluated on the iPhone itself (the Mac-side
`/private/var/db/os_eligibility/eligibility.plist` patch is not enough on
iOS 26+ — the phone rejects the pairing with
`SFAuthenticationErrorCodeRegionLocked`).

Two archives were generated by Project Linwood's
`tools/override_archive/make_override_archive.swift` on 2026-11-14:

| File | Map | Bytes | SHA-256 |
| --- | --- | --- | --- |
| `mirroring.data` | `{27 → 4}` | 492 | `fb5eb97de65dd31268303af3282b8e1f5b8f1c7b9bb20ba1eca770e6fa1af05a` |
| `siri+mirroring.data` | `{27, 96, 122, 155 → 4}` | 700 | `65ad959e0920ea1136d011dd6847df60146d937dcf502aa22f0804812bd32b68` |

Unlike the two Siri-era archives, these are byte-reproducible: they were built
from an ordered list into an `NSMutableDictionary`, whereas a Swift `Dictionary`
iterates in hash-seed order (three runs of the old generator produced three
different SHA-256 values for the same 3-key map). The decoded override map is
identical either way, and that is what `eligibilityd` acts on.

## Why there is a combination table

The device holds exactly ONE override map
(`SysContainerDomain-com.apple.eligibilityd` /
`Library/Caches/NeverRestore/eligibility_overrides.data`), so two enabled
operations cannot each write their own file. `TweakCompiler` resolves the set of
enabled operations to one archive:

| Selected | Archive key | Bytes |
| --- | --- | --- |
| Siri AI | `siri` | 631 |
| iPhone Mirroring | `mirroring` | 492 |
| both | `siri+mirroring` | 700 |
| Reset (wins over the others) | `reset` | 320 |

## Use

Internal Options contains **Siri AI (Ineligible Regions)**,
**iPhone Mirroring (Ineligible Regions)** and **Reset Siri AI Overrides**.
Select, apply, and reboot. Disabling a switch only deselects the operation. To
roll back an applied override, select Reset Siri AI Overrides and apply. This
clears *all* overrides; it does not restore a previous map. The ordinary
Internal Options preference reset does not clear these archives; use the
dedicated switch.

Mobile permits all iPhone models on iOS 27.x. Desktop 9.7.2 requires Apple
Intelligence hardware for enable and allows reset on every iPhone. Mobile
deliberately retains its broader model policy. Only iPhone 16 Pro (`iPhone17,1`),
build 24A437 was reported verified upstream; other builds and hardware are not
verified by us.
Siri language must be English (US); complete Siri AI consent in Settings after
reboot. This does not add German voice support or guarantee server availability.
iPhone Mirroring additionally needs the Mac half: the Mac's own
`OS_ELIGIBILITY_DOMAIN_IRON` in `/private/var/db/os_eligibility/eligibility.plist`.

Delivery requires a prepared unencrypted protective backup. Encrypted backups,
skipping protection, and forced sparse delivery are refused for these payloads.
File: `SysContainerDomain-com.apple.eligibilityd` /
`Library/Caches/NeverRestore/eligibility_overrides.data`, root:root, 0644,
protection class 4; generated directories root:root, 0755, class 0.

No real-device activation has been performed as part of this integration — for
either operation.
